# FlowAgent 量化评估

管理后台“量化评估”页把指标分为两类，禁止混用：

- 生产观测：按最近 7、30 或 90 天的真实 Agent Run、Tool Step、GitHub 写操作、反馈与飞书事件计算。
- 离线基准：固定问题集，可重复运行，便于比较检索或记忆机制改动前后的回归。

## 指标口径

| 指标 | 计算方式 | 无样本处理 |
|---|---|---|
| Tool Call 成功率 | 成功 Tool Step / 全部 Tool Step | 待积累 |
| GitHub Issue 创建成功率 | 成功的真实创建 / 全部创建尝试 | 待积累 |
| Citation 覆盖率 | 使用知识检索且最终答案包含 `[数字]` 或来源 URL 的 Run / 使用知识检索的 Run | 待积累 |
| 平均 Agent Steps | 每个 Run 不同 `step_no` 数量的平均值 | 待积累 |
| 平均响应时间 | 已完成 Run 的端到端耗时平均值 | 待积累 |
| P95 响应时间 | 已完成 Run 端到端耗时的 nearest-rank P95 | 待积累 |
| 重复事件去重率 | 被唯一消息约束拦截的重复投递 / 检测到的重复投递 | 待积累 |
| 多轮上下文成功率 | 含“这个/上述/刚才”等指代的建单请求，在同会话后续 6 条消息（含二次确认）内真实创建成功的比例 | 待积累 |
| 用户正向反馈率 | 正向反馈 / 全部已评价回答 | 待积累 |
| RAG Recall@5 | 预期文档出现在 Top 5 的问题数 / 20 条固定问题 | 不适用 |
| 多轮上下文证据保留率 | 历史 Issue/URL、明确约束、已确认摘要待办仍可进入模型上下文 / 30 组固定场景 | 不适用 |
| 重复事件去重验收 | 同一 message_id 投递 100 次，99 次重复全部被拦截 | 不适用 |
| 高风险确认单次消费通过率 | 确认码首次使用成功且复用失败 / 30 组固定场景 | 不适用 |

## 当前离线基线

- RAG Recall@5：100%（20/20）。原先未命中的 `RAG/Citation/来源` 和 `owner lookup/负责人映射` 已通过领域术语归一化修复，并使用同一问题集复测通过。
- 多轮上下文证据保留率：100%（30/30）。覆盖超出近期窗口后的 Issue/URL、明确约束和已确认摘要待办；该指标验证证据能进入上下文，不冒充线上模型的语义理解成功率。
- 重复事件去重验收：100%（99/99）。同一飞书 `message_id` 连续投递 100 次，仅首条进入处理。
- 高风险确认单次消费通过率：100%（30/30）。确认码首次消费后再次使用均被拒绝。

运行：

```bash
cd backend
python -m app.evaluation.run
```

结果写入 `backend/app/evaluation/latest.json`，后台只读取该次真实运行产物。

## MVP 收尾建议门槛

试运行样本量不足时不应宣称达标。建议累计至少 100 次 Tool 调用、20 次真实 Issue 操作、30 次知识检索回答、20 个重复事件和 30 条用户反馈后，再做正式验收。建议门槛：Tool 成功率不低于 95%，Issue 创建成功率不低于 95%，Citation 覆盖率不低于 95%，重复事件去重率 100%，多轮上下文成功率不低于 90%，RAG Recall@5 不低于 85%。响应时间应结合 DeepSeek 与外部工具网络条件设定，不用单一阈值掩盖慢 Tool。

## 第一轮整改记录

现网 30 天样本显示 9 次 Tool 失败中有 8 次来自 `web_search`，该工具连续 3 次等待全局 15 秒超时，使单次失败接近 45 秒。整改后：

- 量化页面按 Tool 展示调用量、成功率、平均耗时和 P95，并聚合失败原因。
- 页面把 Agent Run、LLM Step 和 Tool Step 的平均/P95 分开，避免端到端数字掩盖瓶颈。
- `web_search` 使用独立的 8 秒超时和 1 次尝试；`open_url` 使用 10 秒超时和最多 2 次尝试。
- 运行配置页显示联网搜索后端和保护参数。国内生产环境建议配置 Bocha API；未配置时不把搜索失败伪装成检索成功。

Citation 整改采用结构化证据契约：知识检索返回有效结果后，`submit_final_answer.citations` 必须引用本轮存在的编号，正文也必须出现对应 `[编号]`。校验失败时要求模型重写一次；系统不做字符过滤、不改写正文，也不会自动生成不存在的引用。
